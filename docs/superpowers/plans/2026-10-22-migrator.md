# Migrator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@wallarm-org/migrator`, a non-interactive CLI that rewrites consumer source for every design-system breaking change between `--from` and `--to`, wired into this repo's release pipeline.

**Architecture:** New workspace package `packages/migrator` (Rslib → single ESM `dist/index.js`, `ts-morph` external runtime dependency). Migrations are files in `src/migrations/`; their design-system versions live in `versions.json`, read at runtime and stamped by a local semantic-release plugin on design-system majors. A PR-level CI check enforces "breaking change ⇒ migration".

**Tech Stack:** TypeScript (strict), ts-morph 28.0.0, semver, `node:util` `parseArgs`, Rslib, Rstest, semantic-release 25, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-22-migrator-design.md` — read it first; section refs below (§n, Dn) point there.

## Global Constraints

- Package name `@wallarm-org/migrator`, bin `migrator`, `"type": "module"`, `"engines": { "node": ">=20" }`, `publishConfig` public npm (copy from `packages/mcp/package.json`).
- `ts-morph` pinned `28.0.0` in `dependencies` (never bundled — D1). `semver` in `dependencies` (exact version from `pnpm view semver version`), `@types/semver` in devDependencies.
- Report file name: `wds-migration.md` (exact), written at cwd root.
- File extensions scanned: `ts, tsx, js, jsx, mts, cts`. Pre-filter substring: `@wallarm-org/design-system`.
- Supported floor: `from >= 1.0.0`. Error copy: `upgrade to 1.x manually first`.
- "Too old" error copy: `design-system X is newer than this migrator knows; retry later or update @wallarm-org/migrator` (X = `to`).
- Exit codes: `0` ran (with or without manual items), `1` usage/version errors (§4).
- Tag format `migrator-v${version}`. Stamp only on `main` and only for `nextRelease.type === 'major'`.
- No `any`; `import type` for type-only imports; Biome formatting (`pnpm biome check --fix packages/migrator`).
- Commits: Conventional Commits, scope `migrator` (or `ci` / `build` for workflow/release-config tasks). **Never `!`/`BREAKING CHANGE`** in these commits.

## Review Focus

1. **`from` inside the range lower bound** — `--from 3.0.0 --to 3.2.0` must NOT select `avatar-size-rename` (its version is 3.0.0; range is exclusive at `from`). Pinned in Task 1 (`excludes migrations at exactly from`).
2. **Same-named local component** — a file that imports `Avatar` from `./Avatar` (or another library) must not be touched even if it also imports something else from the design-system. Pinned in Task 2 and Task 3.
3. **CRLF / non-ASCII source & quote style** — edits must keep `"` vs `'` and line endings. Pinned in Task 3 (`keeps double quotes`, `keeps CRLF`).
4. **Running twice from a monorepo root** (`executionMode: update` per package.json) — second run over the already-migrated tree with the same `from→to` must yield zero changes for literal cases. Pinned by idempotence tests in Tasks 3–4 and in Task 6 (`second run is a no-op`).
5. **Report file left over from a previous run** — D8 says "no file is written" when clean and "an existing file is overwritten" otherwise. So a clean run leaves an existing file untouched (it may hold the team's notes) and a run with manual items overwrites it. Pinned in Task 6 (`overwrites existing report`, `leaves existing report when clean`).
